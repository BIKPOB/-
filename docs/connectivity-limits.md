# Сеть, другой VPN и ограничения доступа

## Что есть в Android 0.4.0

Движки OpenVPN, WireGuard и AmneziaWG входят в APK. «Кодеки» отдельно
скачивать не требуется: скачиваются профили серверов. Каталог VPN Gate
содержит OpenVPN. Для WireGuard/AmneziaWG нужен действующий .conf от
владельца сервера; импорт файла и вставка текста доступны внутри приложения.

База загружается с VPN Gate, при ошибке — из резервного снимка в этом
репозитории. Снимок обновляется ежечасно; приложение не принимает снимки
старше 24 часов. Это повышает доступность каталога, но не гарантирует
доступность самого VPN-сервера. Обе точки загрузки могут быть недоступны.

## Другой VPN на Android

В одном Android-профиле может работать только один системный VpnService.
Запуск Quiet VPN может остановить другой VPN. При включённом для другого
приложения режиме «Всегда включённый VPN» / «Блокировать соединения без VPN»
переключение может потребовать изменения настроек пользователем.
Приложение не должно самостоятельно отключать эти защитные настройки.

Базу можно загрузить через уже работающий VPN, затем переключиться на Quiet
VPN. Доступность сервера при проверке через чужой VPN не доказывает, что
сервер доступен напрямую после переключения. Автоматическая диагностика
чужого VPN пока не реализована.

## Блокировка и отсутствие связи

- DPI-блокировка VPN при работающем интернете: AmneziaWG может помочь
  благодаря маскировке трафика, но результат зависит от сети и конфигурации.
- Блокировка IP или UDP: смена протокола на том же заблокированном сервере
  может ничего не изменить. Нужен доступный сервер и совместимая настройка.
- Разрешены только отдельные адреса («белый список»): обход не гарантирован.
- Подавление радиоканала, отсутствие покрытия или полное отключение передачи
  данных: VPN не создаёт физическую связь; необходим другой доступный канал.
- По одному таймауту приложение не может определить РЭБ, DPI, неисправный
  сервер или неверные ключи. Не показывать «Обнаружена глушилка» без доказательств.

## Следующий этап разработки

Это требования, а не уже реализованные функции:

1. Перед подключением предупреждать о другом VPN, не отключать его скрыто.
2. Разделить отсутствие сети, недоступность каталога, отказ разрешения VPN,
   отсутствие handshake и неуспешную проверку доступа после подключения.
3. Использовать несколько независимых HTTPS-точек проверки. Сейчас одна
   точка gstatic может дать ложный отрицательный результат при её блокировке.
4. Ограничить автоматические повторы и вводить увеличивающиеся интервалы;
   переключать только профили, которыми пользователь разрешил пользоваться.
5. Рассмотреть XRay/REALITY как отдельный движок и серверную инфраструктуру.
   Он не включён в 0.4.0. Поддержка протокола не создаёт бесплатные серверы.
6. Проверить на реальных телефонах переключение VPN, Always-on/lockdown,
   смену Wi-Fi/мобильной сети, UDP/IP-блокировки и отсутствие интернета.
