# Исправление зависания подбора 0.10.1

В 0.10.0 таймер вызывал `HttpClient.close(force:true)`, но не ограничивал ожидающий Future. Локальное воспроизведение: HTTP-прокси отвечает `200 Connection established` на CONNECT и оставляет TLS без ответа. При лимите 150 мс старая проверка оставалась в ожидании более 2 секунд и завершалась только внешним тестовым таймаутом. Общий бюджет подбора тоже не мог разбудить этот Future.

0.10.1 завершает ожидание самостоятельным таймером и сигналом отмены, сохраняя проверку сертификата. HTTPS через один тестовый адрес ограничен вычисленными 6–10 секундами; резервный адрес проверяется отдельно. Запуск/остановка проверочного ядра и чтение маршрута также имеют пределы ожидания. При неподтверждённой остановке автоматический запуск VPN прекращается.

Результат каждого кандидата сразу попадает в диагностику; экран каждую секунду показывает время этапа и число результатов. Статус источников публикуется до запуска прокси. Во время автоподбора скрыта карточка ручного выбора сервера и отключено добавление профиля; импорт собственного ключа сам по себе по-прежнему не включает VPN.

Регрессия `tools/test_candidate_lab.dart` использует настоящие локальные TCP-сокеты: зависший CONNECT, зависший TLS после CONNECT, переход от первой тройки к следующей, отмена во время TLS и очистка локальных прокси. Новый widget-тест проверяет подбор с пустым списком импортов. Прежние тесты параллелизма, скорости, маршрутов и реальные Windows Xray-проверки сохранены.

Это исправляет воспроизведённое зависание клиента; доступность и скорость публичных серверов у конкретного оператора РФ требуют проверки на устройстве.
