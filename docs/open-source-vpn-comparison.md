# Открытые VPN-проекты: база для Quiet VPN

Дата анализа: 2026-10-10. Это сравнение клиентов и серверных инструментов, а не каталог бесплатных работающих серверов. Открытый исходный код не предоставляет доступ к инфраструктуре проекта.

| Проект | Основа и сильная сторона | Применение в Quiet VPN |
| --- | --- | --- |
| [Amnezia](https://github.com/amnezia-vpn/amnezia-client) / [AmneziaWG](https://github.com/amnezia-vpn/amneziawg-go) | Связка клиента и развёртывания своего сервера; модификация WireGuard с параметрами маскировки | Сохранять совместимые AWG-параметры; параметры клиента должны совпадать с сервером. Поддержка отдельных версий AWG требует проверки, не предполагается автоматически |
| [Hiddify](https://github.com/hiddify/hiddify-app) | Многопротокольный клиент на sing-box; удалённые профили, обновления, выбор по задержке | Отделять серверы от источников подписок; показывать результат запроса через прокси; проверять обновление до замены профиля |
| [v2rayNG](https://github.com/2dust/v2rayNG) | Android-клиент Xray; раздельные TCP и реальные прокси-тесты | Различать доступность порта и работу туннеля; ограничивать параллелизм тяжёлых проверок ядра |
| [Outline](https://github.com/OutlineFoundation/outline-apps) | Client и Manager; выдача ключей доступа, обновляемые конфигурации | Организовать контролируемую выдачу профилей и смену адреса без переустановки приложения |
| [WireGuard Android](https://github.com/WireGuard/wireguard-android) | Узкий клиент и встраиваемая библиотека туннеля | Чёткое управление жизненным циклом VPN и конфигурацией. Стандартный WG не следует считать механизмом маскировки AWG |

## Что просмотрено непосредственно в коде

- Hiddify commit `98387fe96b1ce5bc01ec463ab2a0d1a6f0c42d2e`: `lib/features/profile/notifier/profiles_update_notifier.dart`, `lib/features/proxy/data/proxy_repository.dart`, `lib/features/proxy/overview/proxies_overview_notifier.dart`. Интервал обновления зависит от профиля; обновления выполняются последовательно из-за общего native core. URL-тест делегируется sing-box, задержка используется в сортировке.
- v2rayNG commit `6fe3893bfd37865dc677111fa48aef14c0a41efd`: `V2rayNG/app/src/main/java/com/v2ray/ang/service/RealPingWorkerService.kt`. TCP socket test отделён от `measureOutboundDelay`; пул ограничен настройкой concurrency, полные CUSTOM-конфигурации сериализованы mutex. Это важное ограничение для просьбы проверять всё одновременно: сетевые пробы можно распараллелить, пересоздавать общий VPN-движок без ограничений нельзя.
- В Android-интеграции используемого Quiet VPN `flutter_v2ray_client` проверен вызов getConnectedServerDelay: URL передаётся через статическое поле, тогда как VPN-служба работает в отдельном процессе. Quiet VPN 0.7.0 обходит этот путь собственным HTTPS-запросом через локальный SOCKS активного ядра.
- Amnezia/AmneziaWG ранее исследованы при интеграции движка; Outline и официальный WireGuard в этой сравнительной части проверены по официальным репозиториям и документации, без полного аудита их реализации.

Официальная документация динамических ключей Outline: https://developer.getoutline.org/vpn/management/dynamic-access-keys/ . Удалённый документ позволяет менять серверные параметры без перевыдачи пользовательской ссылки. Доступность самого источника обновлений тоже необходимо проверять.

## Общее и вывод для архитектуры

1. Рабочее подключение требует совместимых клиента, серверного движка, параметров и доступного сетевого маршрута. Загрузка дополнительного «кодека» не исправляет неверный ключ или заблокированный адрес.
2. Интерфейс управления профилями отделяется от нативного сетевого ядра. Готовые ядра уменьшают объём собственной реализации, но требуют закрепления версий, проверки лицензий и интеграционных тестов.
3. Пинг/TCP connect и передача данных через туннель — разные проверки. Тайм-аут сам по себе не доказывает блокировку: возможны неработающий сервер, несовпадающие параметры, DNS или недоступная контрольная точка.
4. Обновление профилей и серверной инфраструктуры важнее произвольной загрузки исполняемых компонентов через браузер.

## Реализовано в 0.7.0

OpenVPN и каталог VPN Gate удалены из рабочего приложения. Остались WireGuard с совместимыми параметрами AmneziaWG, VLESS и Shadowsocks. Есть браузер поставщика, перехват поддерживаемых ссылок/конфигураций, импорт файла/буфера и формы параметров. Сохранён параллельный мониторинг адресов. Для VLESS/SS статус connected требует успешной HTTPS-проверки через локальный SOCKS, без прямого fallback.

Сборка: https://github.com/BIKPOB/-/actions/runs/38052563274 . Исходники APK: `c29d3cd1b71cc2d01c52d92b253117f8a27fd6c6`. Версия 0.7.0 (16), ARM64 и ARMv7. SHA256: `a5eed0725b833e624276307fdfda8b4b8b605b2a9bc61285eeb5d44b8aca4895`. Автоматические проверки и сборка пройдены; APK имеет тестовую Android debug-подпись.

## Ещё не реализовано и не подтверждено

- Автообновляемые подписки, динамические ключи Outline, QR-сканер и автоматическая выдача собственных серверов.
- Полноценная проверка каждого профиля через отдельное ядро в списке: существующий параллельный мониторинг измеряет доступность адресов.
- Подключение на Samsung SM-A256E / Android 16 в сети пользователя; реальные действующие конфигурации для трёх протоколов не предоставлены. Успешная сборка этого не доказывает.
- Контрольная HTTPS-точка сейчас одна: gstatic generate_204. Её блокировка может давать отрицательный результат даже при исправном сервере.

Следующий приоритет: контролируемые тестовые серверы для каждого протокола; тесты TCP/UDP/DNS/IPv6 и переключения Wi-Fi/мобильной сети; затем обновляемый источник проверенных профилей и резервные контрольные точки. Не публиковать приватные ключи в репозитории или диагностических логах.
