# Quiet VPN • Flutter MVVM • Windows / Android

Новая реализация клиента на Flutter вместо прежнего Kotlin-проекта.
В поставке: Flutter UI/MVVM, онлайн-каталог VPN Gate, импорт OpenVPN-профилей,
Android-адаптер, Windows-адаптер, опциональный собственный сервер каталога,
Docker/Caddy, тесты и CI.

**Статус: тестовая версия 0.5.2 для Android и Windows x64 собрана.**
Android OpenVPN собирается из закреплённых исходников с OpenSSL 4.0.3;
старый модуль с OpenSSL 1.1.1l удалён. На Android встроены OpenVPN,
WireGuard и AmneziaWG; на Windows реализован OpenVPN.
Прошли анализ, Flutter-тесты, нативный разбор трёх реальных OpenVPN-профилей
и ClamAV (0 обнаружений). Windows OSV: 70 Pub-пакетов, 0 предупреждений.
Реальное подключение на устройстве и утечки ещё не проверены; APK имеет тестовую
подпись. См. [отчёт безопасности](docs/security-audit.md).

## Изменения 0.5.2: WireGuard / AmneziaWG

Обработаны ошибки загрузки JNI, запуска, остановки и отмены системного запроса
разрешения. WG/AWG работает через foreground-службу с уведомлением. Запоздалый
handshake не переводит остановленную сессию обратно в Connected. Импорт сохраняет
новые поддерживаемые движком поля AmneziaWG, включая HeaderProtectionKey.

Добавлены проверки настоящего парсера конфигураций, сервисного уведомления и
сценариев ошибок с тестовым адаптером движка. Реальный TUN/handshake и утечки
на устройстве не проверены; для завершения нужны выданные сервером конфигурации.
Ссылки на официальные способы получения .conf добавлены в «База и протоколы».
Автоматической базы WG/AWG нет. [Подробности и ограничения](docs/wg-lifecycle.md).

## Исправления 0.5.1

- Настройки OpenVPN инициализируются в Android Application до создания сервиса.
  Исправлен найденный путь падения при построении уведомления подключения.
- Панель состояния и подключения прокручивается вместе с лениво создаваемым

## Что работает по архитектуре и реализовано в коде

- Один интерфейс Flutter для Android и Windows; View → ViewModel → repositories/engine.
- Статусы Connecting, Connected, Disconnected, Error; управление одним туннелем.
- Получение VPN Gate CSV по HTTPS и кэш на 15 минут; при отказе сети кэш пригоден
  максимум 24 часа. Просроченный каталог не выдаётся за актуальный.
- Страны, список узлов, выбор сервера, импорт .ovpn, редактирование логина/пароля.
- Не более десяти проб за цикл, не более трёх параллельно, интервал 30–33 секунды.
- TCP latency только для TCP-профилей. Для UDP отображается отсутствие TCP-пробы.
- При сворачивании UI список перестаёт опрашиваться; нативный VPN продолжает работу.
  Это экономит батарею и не выдаёт Dart Timer за надёжный Android background service.
- Android подключает собранный из исходников ics-openvpn через собственные
  MethodChannel/EventChannel;
  устанавливать отдельный OpenVPN Connect на Android не требуется.
- Windows управляет настоящим OpenVPN-процессом через защищённый паролем management
  socket на loopback. Его события определяют состояние; stdout не используется
  для имитации Connected. Нужны OpenVPN Community 2.6+ и Windows-драйвер.
- Connected появляется после native CONNECTED и успешного контрольного HTTPS 204.
  Проверка не доказывает отсутствие DNS/IPv6 утечек или правильность всех маршрутов.
- Приватные импорты и пароли сохраняются через flutter_secure_storage; публичные
  профили VPN Gate — в отдельном обычном кэше. Windows временные профили ограничены
  NTFS ACL текущим пользователем и SYSTEM и удаляются после остановки процесса.

Обновление каталога и TCP-пробы не блокируют VPN-команды. Повторный connect во время
активного туннеля отвергается. События ошибок, таймаут подключения и остановка
обрабатываются отдельно; неудачное отключение сохраняет кнопку повторного отключения.

## Быстрый старт

Проверяемая в CI конфигурация: Flutter **3.32.8**, Dart из Flutter, Python 3.12,
JDK 17, Android SDK 36 (compile SDK), SWIG, NDK 30 для OpenVPN.
Подробности: [сборка OpenVPN](docs/openvpn-source-build.md). Для Windows — Windows 10/11 x64, Visual Studio с Desktop
development with C++ и Windows SDK. Flutter Windows собирается на Windows.

```sh
python tools/bootstrap.py --platforms android
python tools/build_awg.py
python tools/build_openvpn.py
flutter analyze
flutter test
flutter build apk --release --target-platform android-arm64,android-arm
```

На Windows:

```powershell
python tools/bootstrap.py --platforms windows
flutter build windows --release
```

Bootstrap генерирует стандартные Android/Windows runners официальной командой
`flutter create`, восстанавливает авторские main.dart/pubspec и применяет Android
manifest/MainActivity. Это позволяет не включать неподтверждённые платформенные
бинарники и Gradle Wrapper. Запускайте bootstrap один раз в распакованном проекте;
повторный запуск может перезаписать ваши изменения runner-файлов.

Команда `flutter run -d windows` подходит для разработки. Для управления OpenVPN
нужны повышенные права. Release runner manifest запрашивает Administrator.
Цель Android — API 35, минимум API 26. Публикация в магазинах и release signing
не настроены. Нативные зависимости, target SDK и поддержка устройств с
16 КБ memory pages должны быть проверены перед публикацией.

## Windows: VPN-движок

Скачайте официальный OpenVPN Community 2.6+ MSI:
https://openvpn.net/community-downloads/

Установите его вместе с Wintun. Опционально используйте:

```powershell
powershell -ExecutionPolicy Bypass -File tools/install-openvpn.ps1 -MsiPath C:\Downloads\OpenVPN.msi
```

Скрипт проверяет Authenticode-подпись OpenVPN перед запуском установщика. MSI
и драйвер не включены в архив и не скачиваются из непроверенных источников.
Клиент ищет `Program Files/OpenVPN/bin/openvpn.exe` или `runtime/openvpn.exe`
рядом со своим EXE. В runtime нужен полный совместимый набор DLL, а драйвер
всё равно должен быть установлен системно. Одного скопированного exe недостаточно.

Штатное закрытие окна сначала отключает VPN. При принудительном завершении UI
отдельный OpenVPN-процесс может остаться активным: завершите его штатно или в
диспетчере задач. Для промышленного установщика следует вынести управление в
Windows service с узким IPC и job object/process supervision.

## Подключение к серверам

**VPN Gate:** запустить приложение → дождаться каталога → выбрать страну и узел →
«Подключить» → на Android принять системное разрешение VPN. Профиль поступает
из официального каталога. Текущие адреса намеренно не зашиты в код.

**VPNBook:** кнопка VPNBook открывает официальный сайт. Скачать профиль для нужной
страны/протокола, импортировать .ovpn, ввести опубликованные там актуальные
логин/пароль. Смена пароля у провайдера потребует обновления в приложении.

**VPN Jantit:** получить аккаунт на официальном сайте, скачать профиль, импортировать
и ввести реквизиты. Временные аккаунты продлеваются через официальный сайт.
Автоматического создания аккаунтов и обхода капчи нет.

Совместимы self-contained TUN-профили с inline CA и одним remote. Не все OpenVPN
директивы допускаются. Отказ импорта сообщает неподдерживаемую директиву;
не ослабляйте проверку сертификата для обхода ошибки подключения.
Сравнение источников и официальные ссылки: `docs/server-sources.md`.

## Свой сервер каталога — опционально

Клиент по умолчанию обращается прямо к VPN Gate: обязательный backend не нужен.
Папка `infra/` позволяет поставить собственный HTTPS-кэш, снизив число обращений
к каталогу и сохранив работоспособность при кратком отказе upstream.
Это сервер метаданных, **он не создаёт VPN-реле в разных странах**.

На своём хосте с Docker, публичным доменом и доступными портами 80/443:

```sh
cd infra
export CATALOG_DOMAIN=catalog.your-domain.example
docker compose up -d --build
```

Предварительно направьте DNS вашего реального домена на хост. Caddy получает TLS
сертификат. Значение .example приведено только как обозначение, его нужно заменить.
Пересоберите клиент с адресом:

```sh
flutter build apk --debug --dart-define=CATALOG_URL=https://catalog.your-domain.example/v1/catalog.csv
```

Аналогичный `--dart-define` используется в Windows-сборке. Клиент принимает только
HTTPS. Заголовок X-Catalog-Fetched-At сохраняет возраст upstream-данных при кэшировании.
`/healthz` проверяет процесс; `/readyz` отвечает 503, пока нет пригодного каталога.
При сбое обновления сохраняется предыдущая версия, но через 24 часа она истекает.
Docker image tags перед production-развёртыванием следует зафиксировать digest.

Для локальной разработки сервера:

```sh
cd infra
python -m unittest discover -s tests -v
python catalog_service.py --host 127.0.0.1 --port 8080
```

Нет публичного endpoint для загрузки URL, конфигов или реквизитов: upstream фиксирован.
Сервис не собирает IP пользователей в access logs. Он проверяет структуру feed,
размеры и IP, но не заменяет клиентскую политику .ovpn.

## Ограничения и проверка на устройствах

- Бесплатные публичные серверы нестабильны; наличие записи не доказывает доступность.
- Connected означает native session + HTTPS-проверку. При блокировке gstatic проверка
  может дать ложный отказ. Для своего продукта замените адрес на свой endpoint 204.
- HTTPS-запрос не привязан отдельно к TUN: правильность маршрута и exit IP нужно
  проверить на устройстве. Полный kill switch и гарантированная IPv6-защита не реализованы.
- OpenVPN-профилю добавляются проверка назначения сертификата server, auth-nocache
  и IPv4 default route def1, если они не заданы. Сервер по-прежнему должен выдать DNS
  и поддерживать необходимую маршрутизацию. Серверные push-параметры обрабатывает движок.
- TLS, legacy cipher и compression compatibility зависят от конкретного реле.
  Политика отклоняет профили со сжатием/неподдерживаемыми настройками; число
  пропущенных записей показывается. Автоматического снижения TLS security level нет.
- Always-on/reboot recovery и фоновый опрос всех серверов при закрытом UI не реализованы.
  VPN-сервис Android владеет туннелем; OEM/системное завершение требует device testing.
- На Windows клиент управляет только созданным им процессом, не отключая чужие VPN.

Обязательные проверки: два реальных сервера TCP/UDP; отказ permission; неверный пароль;
таймаут; внешний IP и DNS до/после; IPv6; Wi-Fi→LTE; сворачивание и Doze; авария UI;
повторное подключение; Windows без драйвера и без повышенных прав.
